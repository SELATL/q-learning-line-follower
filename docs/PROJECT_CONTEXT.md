## 배경 및 목적 — 대화 근거

LEGO SPIKE Prime의 두 바퀴·두 센서 선 추종 경험을 바탕으로 강화학습과 Tabular Q-learning을 학습한다. 과거 실제 로봇의 세부 구현 자료는 없으며 기억에 기반한 재구성이다. 울퉁불퉁한 시험 트랙에서 멈췄다는 기억은 원인 확정 근거가 아니다.

한때 노이즈와 규칙 개선을 중심으로 한 로드맵이 제안됐지만, 이후 사용자는 익숙한 플랫폼으로 RL 자체를 배우는 방향을 선택했다. 현재 기준은 Q-learning 중심 14일 로드맵이다. PPO·MuJoCo·ROS·신경망은 필수 범위가 아니다.

사용자는 수식의 기존 Q값·학습률·할인율·실패 종료 시 미래 가치 제외를 학습했다. 코드 작성은 도움을 받되 상태·행동·보상과 실험 결과를 설명하는 것이 목표다. 자동 구현 완료를 개념 이해 완료로 간주하지 않는다.

## 현재 상태 — 코드 근거

- 원형 트랙, 차동구동 이동, 좌우 반사광 센서, 규칙 기반 제어, 수동 조작·표시·PNG 저장 구현.
- `LineFollowerEnv`는 `Simulator`를 감싸는 일반 Python 클래스다. `reset()`과 `step(action)`은 센서 NumPy 배열만 반환한다.

- `heading_error()`는 대화에서 제안됐지만 실제 작업본에는 없다.
- Gymnasium 의존성·상속·spaces·seed·종료 신호·reward·상태 이산화·Q-table·학습 루프는 없다.
- Day 3–4 구현 완료, Day 5–6 진행 중. 학습 실험은 시작 전이다.

## 제안된 첫 학습 설계 — 아직 미구현

거리 오차 경계 `[-0.03,-0.01,0.01,0.03]`m와 방향 오차 경계 `[-15,-5,5,15]`도를 사용해 각각 5구간, 총 25상태를 만든다. 상태 번호는 `distance_bin*5+heading_bin`, 행동 3개로 Q-table은 25×3이다. 경계는 각 구간의 하한 포함 방식으로 구현할 예정이며 경계 테스트가 필요하다.

목표 방향은 반시계 원 접선 `atan2(y,x)+pi/2`. 방향 오차는 `robot.theta-target_heading`을 `[-pi,pi)`로 정규화한다. 이는 원형·반시계 주행 전용 설계이며 다른 트랙으로 확장할 때 재설계한다.

보상 초안은 `선 방향 진행 거리/0.006 - abs(이동 후 거리 오차)/0.03`. 실패는 `abs(error)>=0.08`m에서 보상 -10으로 대체하고 종료. 1,000 step(50초)은 시간 제한으로 구분. 진행 거리는 원 각도 차이의 ±pi 경계 처리를 포함해 부호 있는 원호 진행량으로 명확히 정의·검증해야 한다. 계수와 기준은 확정된 최적값이 아니라 실험 시작안이다.

첫 실험은 정확한 위치·방향으로 상태를 만들고 이후 센서만 쓰는 실험과 비교한다. 양쪽 센서가 흰색인 관측만으로 중앙과 이탈을 구분하기 어렵다. 직전 행동을 더해도 완전한 관측이 보장되지는 않는다.

## 문제 및 보존 정책

사용자 작성 중 `self.robot.y` 오류가 있었고 `self.sim.robot.y`로 수정됐다. 실제 사본도 수정된 상태다. 초기 센서는 약 `[14.915,66.825]`로, 두 센서 모두 흰색이 아니다. 센서 전방 위치·트랙 곡률·완만한 반사광 경계에 따른 결과다.

현재 개발 디렉터리와 이전 ZIP 검토용 폴더는 서로 다르다. 이번 사본은 ZIP 검토본이 아닌 실제 개발본을 사용했다. 원본의 중복 하위 `line_follower_sim/`와 `work/` 설치 패키지·캐시는 사본에 포함하지 않았다. 원본 파일은 삭제·변경하지 않았다. 확인한 원본 경로에는 Git 저장소가 없었다. 다른 위치의 저장소 존재 여부까지 단정하지 않는다.

GitHub에는 문서와 소스가 이동하며 기존 채팅 자체가 자동 복원되는 것은 아니다. 이 문서와 초기 프롬프트가 대화 맥락의 인수인계 수단이다.
