## 2026-11-23 — 랜덤 트랙 Q-learning 대시보드 MVP

기존 `robot.py`·`sensors.py`·`track.py`·`simulator.py`·`visualization.py`·`env.py`·`main.py`와 기존 테스트 9개는 수정하지 않았다. 새 파일만 추가했다.

| 파일 | 역할 |
|---|---|
| `line_follower/random_track.py` | 시드별 열린 트랙(직선+원호). 최소 곡률 반경 0.22m, 떨어진 구간끼리 0.20m 이상, 길이 약 3.2–4.6m |
| `line_follower/rl_env.py` | 5행동 모터 표, 12상태, 보상·이탈·완주·시간 제한 |
| `line_follower/qlearning.py` | QAgent(ε-greedy, α·ε 선형 감쇠), 규칙 기반 비교 정책, 평가 함수 |
| `train.py` | 화면 없는 학습 + 미학습 트랙 비교 |
| `dashboard.py` | 3패널 대시보드(시뮬레이터 / Q-table / 학습 지표) |

### 확정한 정의
- 상태 = (왼쪽 흑백, 오른쪽 흑백, 직전 조향 좌/직/우) 12개. 반사광 < 50 이면 검정.
- 행동 = 직진(60,60), 약좌(40,60), 강좌(20,60), 약우(60,40), 강우(60,20). 60 → 0.12 m/s 환산. 기존 Robot의 원호 적분을 상속해 바퀴 속도만 교체.
- 이탈: 센서가 아니라 로봇 중심과 중심선 거리 > 0.07m. 두 센서가 모두 흰색이어도 이 거리 안이면 계속 진행.
- 완주: 진행 거리 ≥ 트랙 길이 − 0.03m 이고 이탈 아님.
- 한 step에는 완주(+50) / 이탈(−20) / 진행 중 보상 중 하나만 적용. 진행 중 = −0.05 + 2×중심도(앞으로 갔을 때) − 1(좌↔우 즉시 반전). 중심도 = max(0, 1 − 거리/0.07).
- 시간 제한(트랙 길이 기준 직진 소요 step × 2.5)은 truncated로, 미래 가치 bootstrap 유지.

### 보상 초안에서 바꾼 점과 근거 (실험)
1. 처음엔 "+2를 진행량에 비례"시켰다. 회전 행동은 원래 느려서(약조향 0.10, 강조향 0.08 m/s) 회전 자체가 벌점이 되었고, greedy 정책이 오른쪽 센서가 검정인데 왼쪽으로 가는 등 100 에피소드마다 0%↔100%로 뒤집혔다(step 추적으로 확인). → step당 고정 보상으로 되돌림. 할인율이 있으면 느리게 가도 가치가 늘지 않는다.
2. "선 폭 안이면 +2"(band)보다 "중심에 가까울수록 최대 +2"(linear)가 덜 흔들려 linear 채택. band는 `CENTERING_MODE`로 남겨 비교 가능.
3. 고정 α=0.1에서 greedy 정책이 흔들려 α를 0.1→0.01(400 에피소드)로 감쇠.

### 검증 결과 (Linux, Python 3.13.18, NumPy 2.5.3, Matplotlib 3.11.2)
- 규칙 기반: 미학습 트랙 30개 완주율 100%.
- Q-learning(시드 1, 500 에피소드, 약 63초): 미학습 트랙 30개 완주율 100%, 완주 평균 750 step(규칙 724 step).
- 시드 1–7, 500 에피소드 후 미학습 15개: 6개 시드 100%, 1개 시드 80%. 300 에피소드 이전 greedy 성능은 시드에 따라 크게 흔들린다.
- 테스트 22개(기존 9 + 신규 13) 통과. 대시보드는 Agg 백엔드 PNG와 프레임 루프로만 확인. Mac 실제 창·버튼은 미검증.

### 한계
- 현재 트랙에서는 규칙 기반도 100%라 Q-learning이 규칙보다 낫다는 근거는 없다. "규칙 없이 보상만으로 같은 수준에 도달"까지가 현재 주장 가능한 범위.
- 선 위 상태(WB/BW/BB)의 Q값 차이는 0.1 수준으로 작다. 학습의 실질 차이는 선을 잃었을 때(WW)의 복귀 방향에서 난다.
- 센서 잡음·급곡선(반경 < 0.22m)·교차로 없음.
